# Conformance

How far this library is from drawing SVG correctly is measured against a published corpus, with every case
counted whether or not the library can draw it. This page says what is measured, what a number means, and where
the tolerance comes from. It is a measurement, not a claim: the score file is regenerated by `make conformance`.

## The corpus

[`linebender/resvg-test-suite`](https://github.com/linebender/resvg-test-suite), pinned by commit in
`tools/resvg-tests/VERSIONS` and fetched into the ignored `third_party/resvg-tests/` by
`tools/resvg-tests/fetch.sh`. It is MIT licensed (its fonts carry their own SIL OFL and Apache 2.0 notices);
nothing of it is copied into this repository. At the pinned commit it holds **1,679 cases**: an SVG file under
`tests/` and a reference PNG beside it. The population is read from the tree, never from a list kept here, and
the scorer fails when it differs from the pinned count or when a case has no reference.

## Outcomes and the score

Every case gets exactly one outcome.

| Outcome | Meaning |
| --- | --- |
| `PASS` | The document loaded, the lowering reported **no refusal at all**, and the render is within the tolerance of the reference. |
| `ACCEPTED` | Rendered outside the tolerance of the reference, and a reviewed row of `tools/resvg-tests/ACCEPTED` says why this library's drawing is the correct one. |
| `FAIL` | Loaded, lowered with no refusal, rendered, outside the tolerance. |
| `REFUSED` | Loaded, and the lowering reported one or more refusals. The render is not scored: a drawing that left something out cannot pass, even when the reference happens to be blank. A lowering that dropped diagnostics past the cap is also refused. |
| `NOT_LOADED` | The load failed. |
| `EXCLUDED` | A rule of `tools/resvg-tests/CASES` names it. It is not run, so it cannot pass. |
| `ERROR` | The harness failed on it: a reference that does not decode or is too large, a render error, a crash, a timeout. |

The **score** is the cases **determined correct**, `PASS`, `ACCEPTED`, and the `FAIL`s classed `EDGE` or `ORACLE_AGREES` (below), over **all** cases, excluded ones included.
The reference image is one oracle among several, so matching it is one way to be correct and not the only one: a case
whose behavior the specification leaves undefined, a case on which the oracles disagree, and a case whose
specification text decides against the reference are correct when a reviewed row says so. `PASS`, `ACCEPTED`, `EDGE` and `ORACLE_AGREES` are
printed apart, so the share that matches the reference is never read as the whole. The score file also prints the
determined-correct ratio over all cases but the excluded, labelled as not the score, so the reach of the milestone can
be read without that ratio standing in for the first.

An accepted case is a reviewed row of `tools/resvg-tests/ACCEPTED`, one case at a time, never a glob: the case, a kind
(`UNDEFINED`, `DISAGREEMENT` or `SPECIFICATION`), the evidence (what the oracles drew, with the numbers), the reason, and
what the runner reported for the case when it was reviewed. The scorer refuses a row for a case that now passes, is
refused or errors, a row for an excluded case, a row whose report no longer matches the drawing, evidence or a reason of
fewer than three words, and a case named twice, so a row cannot go stale unseen. The evidence is measured: Chromium
156, `resvg` 0.45.1 and Inkscape 1.4 render the case at the size of the reference and the distance of this library's
drawing from each is read.

The reference of a case the corpus marks undefined behavior (`UB` in the title) is not a drawing: it is the two letters
UB. It never matches, so each such case is correct only through a row.

An exclusion is a reviewed row of `CASES`: a path or, for a feature that is outside the milestone, a glob, with a
class (`OUT_OF_SCOPE`, `ENVIRONMENT`, `REFERENCE`) and a reason. The scorer refuses an unknown class, a reason of
fewer than three words, a glob outside `OUT_OF_SCOPE`, a rule that matches nothing and a case named twice.

A row of `ACCEPTED` is not a measure of how close a drawing is. A case whose drawing differs from its reference only along
the anti-aliased edges, or in the color of fully transparent pixels, is not accepted for that: it stays a `FAIL` until the
metric is changed, not the case.

### Every `FAIL` is explained

The score file tallies the `FAIL`s by kind and the scorer fails when one has none. The runner reports, beside the strict
figures, `white-over`: the pixels that differ by more than the tolerance's level once both images are composited on white.

- **`EDGE`** is a `FAIL` whose `white-over` is within the tolerance's share of pixels. It differs from the reference along
  anti-aliased edges, or in the color of pixels that are fully transparent in one image, which the strict comparison of
  straight RGBA counts and a viewer cannot see. The scorer measures it; it is not a row.
- Every other `FAIL` is a reviewed row of `tools/resvg-tests/FAILS`, one case a line, with the distances it rests on: in
  pixels over the level, composited on white, ours against the reference and against fresh renders by Chromium, resvg and
  Inkscape, and each of those against the reference. **`ORACLE_AGREES`**: a fresh render by a pinned oracle is within the
  tolerance of ours, so the reference differs from what that oracle now draws; **`ORACLE_SPLIT`**: the oracles disagree
  among themselves; **`DEFECT`**: ours, open, with where it belongs. A row is refused when its case no longer fails, has
  become edge-only, or reports differently from the report reviewed.

`EDGE` and `ORACLE_AGREES` count as determined correct, each printed on its own line: an `EDGE` case differs from the
reference only where a viewer cannot see it, and an `ORACLE_AGREES` case is drawn as a fresh render by a pinned oracle
draws it. `ORACLE_SPLIT` and `DEFECT` are never counted.

## How a case is scored

The runner (`tests/conformance/runner.c`) takes each case through the public API only: `gvec_doc_load` on a file
stream, `gvec_doc_lower_list` into a list, `shape-cpu` to render the list into a straight 8-bit RGBA raster of the
reference's size, `image` to decode the reference (converted to straight 8-bit RGBA when it is not). Each case
runs in a child process under a time limit and an address-space limit, so a hang or a crash is that case's
`ERROR` and the run continues. The runner reads no environment variable and no clock; the score file has no
timestamp, and two runs of the same tree give the same bytes.

The comparison gives two numbers: the largest per-channel difference over all pixels, and the number of pixels
that differ by more than 1/255 in any channel. Two pixels that are both fully transparent are equal whatever
their colour channels hold. A case passes when the first is at most `max-diff` and the second at most
`max-bad-ppm` parts per million of the pixels (`tools/resvg-tests/TOLERANCE`), and when the sink reported nothing it
refused or approximated.

## The tolerance is measured

`shape-cpu` computes exact area coverage; `resvg` and Inkscape each anti-alias in their own way, and the
reference PNGs are the suite's own, not the output of any renderer used here. So how close is close enough is a finding,
not a choice. `TOLERANCE` held zero (which only an exact match meets) until a pair was set from this table and from the
planted defects below; it is now `max-diff 32` and `max-bad-ppm 2000`. A nonzero pair with no named evidence is refused
by the scorer.

`make oracle-tolerance` renders every in-scope case with each oracle in its pinned image, at the reference's size,
and compares each render with the reference and the oracles with each other. The oracles are `resvg` 0.45.1 and
Inkscape 1.4, both installed from the distribution's packages into images built from a dated Debian snapshot
(`tools/oracle/containers/`); nothing of either project is read, copied or linked, and `tools/oracle/oracle-exec`
refuses to run (exit 2, with the reason) when the engine, the image or the version is not the pinned one.

Measured over the 766 cases this milestone does not exclude (the pair of numbers per case is in the generated
`table.tsv`):

```
pair                       n status   exact   p50   p90   p99   max |  ppm p50  ppm p90  ppm p99  ppm max
resvg-vs-reference       763      3      73    16   255   255   255 |       16    14416   640000   992080
inkscape-vs-reference    763      3       8   128   255   255   255 |     4276   506928   640016   965464
resvg-vs-inkscape        760      6       5   128   255   255   255 |     4308   382400   640000   964700
```

`n` is the cases compared; `status` the cases with no comparison (the oracle failed, or wrote nothing); `exact`
the cases with a largest difference of zero; the percentiles are of the largest per-channel difference, and of the
bad pixels in parts per million.

What this says. `resvg` is close to the references at the median (a largest difference of 16 levels and 16 parts
per million of differing pixels), and Inkscape is far from both: against the references and against `resvg` its
median is 128 levels and about 4,300 parts per million. Every pair reaches 255 at the 90th percentile, because the
population includes cases an oracle does not draw as the reference does, so the upper percentiles are not the
typical error. The distance is a floor: no tolerance tighter than the distance two independent renderers keep from
each other can separate a correct drawing from a wrong one. The pair for this library's own output is therefore
set from its measured distance to the references over the cases it draws, and from this table, not before a
case that draws something can be compared with its reference.

## The tolerance pair

`max-diff 32` and `max-bad-ppm 2000`: a case passes when no channel of any pixel differs from the reference by more than 32
of 255, and no more than 2,000 in a million pixels differ by more than 1.

Why a pair at all. The references are not any renderer's exact output: most are palette-reduced PNGs (518 of the 766 in-scope
ones are indexed, 155 grayscale with alpha, 93 RGBA), so even `resvg`, which is the closest, reproduces only 44 of the 494
cases this library draws bit for bit, and the pixel it gets wrong is typically wrong by the palette's rounding. Inkscape's
median largest difference from the references over the same cases is 147 of 255, ours 25 and `resvg`'s 16.

Why this pair. Each number does a different job. The count of differing pixels (`max-bad-ppm`) refuses anything that moves
much of the picture: every planted defect below changes many pixels by more than one level, so a limit of 2,000 in a million
(500 pixels of a 500 by 500 reference) refuses them. The largest difference (`max-diff`) refuses a small element that is
missing or badly wrong, which moves few pixels by a lot. The pair was chosen on the cases this library draws (494 compared
with both oracles): it accepts 227 of them in the sweep (the scorer counted 228 passes in all before the fixes below, 244 after), `resvg` 248 and Inkscape 195, and a looser limit (48 levels, 5,000 in a million)
started to accept the smallest planted shift.

How it is shown to refuse. `make tolerance-planted` (`tools/resvg-tests/tolerance_planted.py`) takes the in-scope cases that
`resvg` draws within the pair (405 of 766), renders each again with its content wrapped in a slightly wrong group, and
compares that render with the same reference. Over the cases where the defect changed `resvg`'s own picture by more than one
level, the pair refused all of them:

```
defect         cases  refused  accepted
shift-0.04        36       35         1   (reported, not required)
shift-0.08       396      396         0
shift-0.2        396      396         0
grow-0.2pct      396      396         0
grow-0.5pct      396      396         0
fade-2pct        396      396         0
fade-5pct        396      396         0
```

The amounts are in user units (the references are 2.5 times the viewBox of most cases): 0.08 is a fifth of a pixel, 0.2 half a
pixel, and the growth and fade are of the whole picture. The smallest shift, 0.04 (a tenth of a pixel), is the limit of what
the pair sees: on a smooth gradient (`painting/stroke/linear-gradient`) it moves a pixel by one or two levels, which no pixel
tolerance can tell from rounding, so it is reported and not required.

The patches are local: one rectangle laid over the picture. `patch-strong` is 4 by 4 user units (about 100 pixels of a
500 by 500 reference) of black at 30% and is wrong by more than the largest difference allows; `patch-wide` is 16 by 16
(about 1,600 pixels) at 3%, wrong by a few levels over more pixels than the count allows. A patch counts only where it moved
`resvg`'s own picture by more than twice the limit it is meant to break, so that `resvg`'s distance from the reference,
which the pair allows, cannot account for the result; on a dark gradient the same patch is no defect and is left out.
`patch-faint` (4 by 4 at 3%) is under both limits and is accepted by design: it shows where the pair stops seeing.

What the pair does not claim. A wrong color of up to 32 levels over up to about 500 pixels passes, and the `patch-faint`
row is that case. The pair is a first setting and is expected to be refined as the oracle tables and the planted defects grow.

## The score today

The lowering draws structure, solid and gradient fills and strokes (with their dashes, caps, joins and `paint-order`) of `path`, `polygon`, `polyline`, `line`, `rect`, `circle` and `ellipse`, including elliptical arcs, and the markers of those; it refuses what it cannot draw yet
(`refusals.md`), and a case that is refused is never scored as a pass. At the pinned commit the score is **1,114 of 1,679
(66.35%)** determined correct, of which **419 (24.96%)** match the reference, **23 (1.37%)** are accepted, **544 (32.40%)** are `EDGE` and **128 (7.62%)** are `ORACLE_AGREES`, with the tolerance at `max-diff 32` and `max-bad-ppm 2000`. At a tolerance of zero it was 6 (0.36%). The 740 `FAIL`s are the 544 `EDGE`, the 128 `ORACLE_AGREES`, 68 `ORACLE_SPLIT` (a `tref` to an element of another file, text along a curve, whose turned glyphs each engine rasterizes differently, vertical text, whose engines place glyphs differently, right-to-left text anchored at the start, which resvg does not flip, the `ch`, `ic`, `lh` and `rlh` units, which depend on font metrics, a marker that draws itself, which each engine cuts differently, two patterns that refer to each other, which each engine cuts at a different place, a mask of masks that name each other through their children, and a pattern in the units of the box painted for a rotated group) and no `DEFECT`.

### What the runner reads from a sink

The runner loads each document with the reference's size as its viewport (the size a browser gives it, which matters
for a document with no `width` and `height` of its own), lowers it with a `GVEC_Lower_Trace`, and renders it. A sink
that reports an item it refused or approximated makes the case `REFUSED`, not `PASS`, even when the pixels agree, with
the report entry mapped back through the trace to the element and line that drew it (`sink-report=N first=element:line`,
or `first=unplaced` for an entry that is about no item). `check-conformance` plants a lowering whose sink refuses an
item and requires `REFUSED`, and `check-conformance-planted` plants the runner ignoring the sink's report.

## Running it

```sh
tools/resvg-tests/fetch.sh            # once
make conformance PREFIX=...           # score the corpus
make check-conformance PREFIX=...     # the harness shown to work
make check-conformance-planted PREFIX=...   # and shown to fail on a planted defect
make oracle-images                    # build the oracle images
make oracle-tolerance PREFIX=...      # measure the oracles
```

`check-conformance` needs no corpus and no oracle. The checks that need a container engine and the built images
are skipped, counted in its summary line, and fail instead when `GHOTI_ORACLE_REQUIRED=1`.
