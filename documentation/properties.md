# SVG properties

Generated by `tools/svg2/gen-tables.py` from `tools/svg2/properties.tsv` and the SVG 2 Candidate Recommendation's property index (Appendix H) and presentation attribute list (chapter 6.6); do not edit. The cascade, the inheritance and the computed values are `text`'s; this page says, for each of the 78 properties the style layer names, where the registry's definition comes from, how `gvec_svg_get()` reads it, and what a percentage of it is of.

The sources: **generated** is the definition of the pin the registry of `text` is made from, which stands; **registered** is a property the pin lacks, which this library adds; **overridden** is one the pin defines differently from the CR (or cannot decide a value for), which this library redefines, and every override is reported by `gvec_svg_style_context_override_at()`. A property of the CR's index or presentation attribute list that is in none of the three fails the generator, and a registered or overridden definition that the registry does not hold fails the property tests.

Types: **keyword** is the computed value as text; **length** is in user units; a percentage of a length is of the **width** or **height** of the nearest viewport (its `viewBox` size when it has one) or of their **diagonal** `sqrt((w² + h²) / 2)`; **shorthand** has no value of its own.

## Registered and overridden definitions

### `color-rendering` (registered)

- inherited: yes
- initial value: `auto`
- value: `auto | optimizeSpeed | optimizeQuality`
- why: SVG 2 CR, Appendix H: `auto | optimizeSpeed | optimizeQuality`, initial `auto`, inherited. The served drafts dropped the property; browsers still accept it, and it never changes the picture.

### `fill` (overridden)

- inherited: yes
- initial value: `black`
- value: `none | <color> | <url> [ none | <color> ]? | context-fill | context-stroke`
- why: CSS Fill and Stroke 3's <paint> has no <color> (`fill: red` is invalid by the pin); SVG 2 section 13.2: "<paint> = none | <color> | <url> [none | <color>]? | context-fill | context-stroke".

### `glyph-orientation-horizontal` (registered)

- inherited: yes
- initial value: `0deg`
- value: `<angle> | <number>`
- why: SVG 1.1 section 10.7.3 (deprecated in SVG 2, still a presentation attribute of the CR's list): `<angle>`, initial 0deg, inherited.

### `glyph-orientation-vertical` (overridden)

- inherited: yes
- initial value: `auto`
- value: `auto | <angle> | <number>`
- why: The pin's text is not a definition (the property has no grammar); SVG 2 CR Appendix H: `auto | <angle> | <number>`, initial `auto`, inherited.

### `stop-color` (overridden)

- inherited: no
- initial value: `black`
- value: `currentcolor | <color>`
- why: The pin gives the property no initial value (and does not say whether it inherits); SVG 2 CR Appendix H: initial `black`, not inherited.

### `stop-opacity` (overridden)

- inherited: no
- initial value: `1`
- value: `<opacity-value>`
- why: The pin gives the property no initial value; SVG 2 CR Appendix H: initial 1, not inherited.

### `stroke` (overridden)

- inherited: yes
- initial value: `none`
- value: `none | <color> | <url> [ none | <color> ]? | context-fill | context-stroke`
- why: As fill.

### `stroke-width` (overridden)

- inherited: yes
- initial value: `1px`
- value: `<length-percentage [0,∞]> | <number [0,∞]>`
- why: CSS Fill and Stroke 3 makes it a comma separated list, one width for each stroke layer, and adds the <line-width> keywords; SVG 2 section 13.3 and the browsers take one <length-percentage> or <number>, and a list is invalid.
